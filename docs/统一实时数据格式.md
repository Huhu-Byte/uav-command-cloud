# 统一实时数据格式

> 阶段 C 第 1 项。本文定义网页、模拟器和后续 DJI Cloud API 之间的稳定数据边界。真实 DJI 的原始报文不得直接透传给网页。

## 1. 使用位置

- REST：`GET /api/v1/dashboard/status`
- 实时推送：`ws://<服务地址>/ws/drone-status`
- 当前版本：`schemaVersion: "1.0"`

两个入口都返回同一种 `RealtimeStatusSnapshot`。模拟器先把自己的数据转换为该格式；以后接入 DJI Cloud API 时，也必须完成同样的转换。

## 2. 顶层字段

| 字段 | 含义 | 当前示例 |
|---|---|---|
| `schemaVersion` | 数据格式版本，字段有不兼容变化时才升级 | `1.0` |
| `source` | 数据来源与接收信息 | 本机模拟器 |
| `updatedAt` | 后端生成此快照的 UTC 时间 | ISO-8601 时间字符串 |
| `staleAfterSeconds` | 页面多久未收到新数据就应认为数据过期 | `10` |
| `task` | 当前巡检任务状态 | 任务编号、状态、进度、点位、高度 |
| `summary` | 指挥中心汇总数值 | 在线设备数、今日里程、点位数 |
| `devices` | 设备状态列表 | 设备编号、连接状态、电量、高度、更新时间 |
| `alerts` | 告警状态列表 | 告警编号、级别、关联设备、确认信息 |
| `returnCommand` | 返航控制指令的当前状态 | 指令编号、状态、进度、结果记录 |

## 3. 来源与时间规则

`source.type` 当前为 `SIMULATOR`，后续真实接入时使用 `DJI_CLOUD_API`；`source.id` 必须能说明具体连接或测试设备，不能放密钥、令牌或账号。

`updatedAt` 和每台设备的 `updatedAt` 均采用 UTC 的 ISO-8601 格式。网页按 `staleAfterSeconds` 判断数据是否过期：超过时只提示“数据可能已过期”，不猜测设备仍在线，也不自动发送控制操作。

页面每秒重新判断数据时效。数据过期、缺少来源或更新时间、缺少关键对象、版本不支持、过期时限无效、时间格式错误时，页面会显示原因，并禁用返航和告警确认；只有收到下一份有效快照后才恢复控制入口。设备 `connectionStatus: OFFLINE` 会单独显示为离线提醒，不会被误报为数据格式错误。

## 4. 统一状态值

| 对象 | 可用状态值 |
|---|---|
| 任务 `task.status` | `EXECUTING`、`RETURNING`、`COMPLETED`、`ABORTED` |
| 设备连接 `connectionStatus` | `ONLINE`、`OFFLINE` |
| 设备运行 `operationalStatus` | `IDLE`、`FLYING`、`RETURNING`、`RETURNED`、`OFFLINE` |
| 控制指令 `returnCommand.status` | `IDLE`、`IN_PROGRESS`、`SUCCEEDED` |

页面只把这些固定状态转换为中文展示，不再依赖模拟器或未来 DJI API 的原始中文描述。

## 5. 控制安全边界

`returnCommand` 是返航命令的状态回执，不代表允许向真实设备发送返航。当前仍只有本机模拟返航；真实设备接入前必须完成测试设备的只读验证、认证、超时重试、错误日志和单独的控制权限验收。
