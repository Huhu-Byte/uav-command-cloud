# 同事交接说明

## 项目现状

这是无人机巡检**网页版演示系统**。当前已完成：

- 指挥中心、实时监控、任务管理、设备管理、事件管理、成果中心、操作历史、系统管理页面。
- 模拟实时状态经 WebSocket 推送到网页，包含设备、任务、告警和返航状态。
- 演示身份与权限、返航二次确认、告警确认、统一操作历史和本机数据库留痕。
- 任务资料的创建、读取和待执行任务编辑；成果清单的读取、筛选和 CSV 导出。
- 本机 H2 或未来 MySQL 的数据库建表脚本；统一实时数据格式和 DJI Cloud API 的安全配置边界。

## 明确未完成 / 不要误用

- 未连接真实 DJI Cloud API、真实无人机、真实视频流或正式登录。
- 页面中的视频、照片预览和设备画面均为占位展示，不包含真实媒体文件。
- 航线规划暂缓；不做 App。
- 默认 `UAV_DJI_CLOUD_ENABLED=false`，不会主动连接或控制真实设备。
- 真实设备只可在测试设备、官方认证资料齐全且使用者明确同意后做**只读验证**。

## 源码包包含与排除

**包含**：后端 Spring Boot 源码、前端 Vue 源码、Flyway 数据库脚本、自动化测试、环境变量示例和项目文档。

**不包含**：本机 H2 数据库、`node_modules`、`target`、`dist`、日志、临时文件、Git 历史、个人工具目录、真实数据库密码、DJI 凭证和 `.env.local`。

## 启动方式

1. 安装 Java 17、Maven 3.9+、Node.js 20+。
2. 将项目放在**不含中文字符的路径**，例如 `C:\work\uav-command`。Windows 下从中文目录启动 Spring Boot 可能失败。
3. 在 `backend` 执行 `mvn test`，再执行 `mvn spring-boot:run`。
4. 在 `frontend` 执行 `npm install`，再执行 `npm run dev -- --host 127.0.0.1`。
5. 浏览器打开 `http://127.0.0.1:5173`。

前端开发服务会把 `/api` 和 `/ws` 自动转发到本机后端 `8080` 端口。若前后端必须分开部署，复制 `frontend/.env.example` 为 `.env.local` 并填写完整地址；不要提交该文件。

## 验收清单

- 后端：在 `backend` 执行 `mvn test`，当前应通过 **13 条测试**。
- 前端：在 `frontend` 执行 `npm run build`。
- 网页：确认左侧导航可切换；任务和成果页能读取数据；系统管理页显示 DJI 接入为未启用/未就绪。
- 安全：不要切换真实凭证或改为启用 DJI；演示返航、告警确认仅可用于本机模拟数据。

## 数据库与部署

- 默认使用同事自己用户目录下的 H2 文件数据库，首次启动会创建演示数据。
- 共享环境使用 MySQL：设置 `SPRING_PROFILES_ACTIVE=mysql`，并提供 `UAV_DB_URL`、`UAV_DB_USERNAME`、`UAV_DB_PASSWORD`。
- 数据库说明见 `docs/数据库部署说明.md`；真实接入边界见 `backend/README.md` 与 `docs/统一实时数据格式.md`。

## 接手后的建议顺序

1. 先完整执行本机测试、构建和网页验收。
2. 优先修复现有页面/接口问题，保持任务、成果和历史的数据闭环。
3. 取得测试设备与官方资料、并获明确同意后，再准备真实设备**只读**验证。
4. 不提前开发 App、航线规划或真实控制能力。

## 给同事的一句话

“请先在无中文路径的本机环境跑通 `mvn test`、`npm run build` 和网页验收。当前所有飞行、视频和 DJI 接入均为模拟或占位，绝不能填入真实凭证或操作真实设备。”
