# 开发规范文档

> 适用项目：上云api私有化部署
> 小白友好版 — 够用、不乱、好上手
> 新对话请先读此文档

---

## 一、项目结构（目录怎么摆）

项目根目录大概长这样：

`
上云api私有化部署/
├── backend/          # 后端代码（Java Spring Boot）
├── frontend/         # 前端代码（Vue 3）
├── ai-service/       # AI 推理服务（Python + YOLOv8）
├── deploy/           # 部署相关（Docker Compose、nginx 配置等）
├── docs/             # 文档
├── scripts/          # 工具脚本
└── .project-memory.md  # 项目记忆文件（自动维护）
`

> 这样分的好处：每种代码各归各类，不会混在一起，找东西好找。

## 二、Git 怎么用

### 2.1 分支命名

| 场景 | 分支名示例 |
|------|-----------|
| 加新功能 | feature/xxx 比如 feature/航线规划 |
| 修 Bug | fix/xxx 比如 fix/地图加载失败 |
| 小调整 | chore/xxx 比如 chore/更新依赖 |

### 2.2 Commit 怎么写

一句话说清楚就行：

`
[类型] 简短描述
`

比如：
- [feat] 添加航线规划页面
- [fix] 修复无人机状态不同步
- [docs] 更新部署文档

> 不要写"修改了一些东西"这种话——别人看不懂，你自己过两周也看不懂。

### 2.3 什么时候提交

- 一个功能做完一部分，可以跑起来了 → 就提交
- 不要攒几百行才提交一次
- 提交前加一下 .gitignore，别把编译产物、node_modules、环境配置传上去

## 三、代码风格（简单规则）

### Java 后端
- 类名：大驼峰，比如 DroneController.java
- 方法名/变量名：小驼峰，比如 getFlightPath()
- 缩进：4 空格，不要用 Tab
- 加注释：写清楚"这段代码是干嘛的"，不要写"这里加了一个变量"这种废话

### Vue 前端
- 组件文件：大驼峰，比如 FlightMap.vue
- 变量/函数：小驼峰
- 尽量用组合式 API（<script setup>），不要用选项式 API

### Python AI 服务
- 文件名/函数/变量：小写+下划线，比如 detect_objects.py
- 缩进：4 空格

## 四、API 接口约定

和大疆上云 API 对接时：

- 所有接口返回统一格式：

`json
{
  "code": 0,
  "message": "success",
  "data": { ... }
}
`

- code = 0 表示成功，非 0 表示错误
- 接口地址统一加版本号：/api/v1/...

---

## 五、数据库约定

- 表名：小写+下划线，比如 uav_flight_record
- 主键统一叫 id，自增
- 每个表加三个字段：
  - created_at 创建时间
  - updated_at 更新时间
  - deleted_at 删除时间（软删除用，0 表示未删除）
- 建表语句统一用 Flyway 管理（放到 ackend/src/main/resources/db/migration/）

## 六、配置文件

| 环境 | 配置文件 |
|------|---------|
| 本地开发 | application-dev.yml |
| 测试 | application-staging.yml |
| 正式部署 | application-prod.yml |

- 敏感信息（数据库密码、API Key 等）不要写在代码里
- 用环境变量或 .env 文件管理

## 七、常用命令速查

`ash

cd backend && ./mvnw spring-boot:run
cd frontend && npm run dev

# 构建后端
./mvnw clean package -DskipTests

# 构建前端
npm run build

# Git 常用
git status                  # 看改了哪些文件
git add .                   # 暂存所有改动
git commit -m "[feat] xxx"  # 提交
git push                    # 推送到远程
`
