# 开发路径与迭代计划

> 本文是后续开发的导航图。新增功能、调整优先级或准备部署前，先对照本文，避免为了增加页面而跳过安全、数据和验收环节。

## 一、项目目标与边界

**目标**：完成一个网页版无人机巡检指挥系统。产品形态和界面信息架构参考大疆司空 2，但不复制其商业功能；系统先用模拟数据跑通“看状态 → 发现告警 → 人工确认 → 安全控制 → 留痕查询”的完整流程，再逐步接入真实设备和共享部署环境。

**当前不做的范围**：AI 识别、手机 APP、单兵设备端 APP、未验证安全条件的真实无人机控制、未确认需求的复杂大屏功能。

**总原则**：先保证后端判断和记录正确，再增加前端按钮；先在本机模拟环境验收，再接入云端或真实设备。

## 对标原则：大疆司空 2

官方参考页面：`https://enterprise.dji.com/cn/flighthub-2`

大疆司空 2 的官方定位包括远程控制、智能任务规划、多类型航线管理、开放集成，以及面向安防、应急、测绘和巡检的空地一体作业。项目以此作为**长期产品方向**，具体采用以下方式：

- **界面参考**：参考其“地图/任务为中心、设备与告警可快速进入、控制结果可追溯”的信息层级；后续界面改动要服务于当前功能，不能单独为了接近视觉效果而新增无后端支撑的页面。
- **功能参考**：按“实时态势 → 任务与航线 → 设备控制 → 资料成果 → 开放集成”逐步建设，不跳过权限、安全检查和操作留痕。
- **范围约束**：当前优先完成阶段 A 的登录、权限、二次确认和操作历史；任务规划、地图能力和资料管理分别留在后续阶段，不抢占当前主线。

## 二、当前基线（2026-07-23）

已完成：

- Vue 指挥中心、任务管理和事件管理演示页面。
- 模拟无人机状态经 REST 与 WebSocket 推送到前端。
- 模拟告警确认闭环、返航安全检查和返航进度展示。
- 返航操作记录、告警确认记录写入本机 H2 数据库；代码已支持后续切换 MySQL。

尚未完成：

- 真实登录、令牌权限。
- 云端 MySQL/ECS 部署、多人共享访问、真实 DJI Cloud API 与设备接入。
- 航线编辑、任务创建调度、成果文件管理和智能管控。

## 三、阶段路线

### 阶段 A：本机安全闭环（当前阶段）

**目的**：即使暂不购买云服务器，也让演示系统具备可信的控制流程。

**开发顺序**：

1. 增加演示登录和两类角色：飞行操作员、管理员。**（已完成）**
2. 控制按钮按角色显示；后端同时校验角色，不能只依赖前端隐藏按钮。**（已完成）**
3. 为返航增加二次确认弹窗，明确展示设备、任务进度、电量和安全检查结果。**（已完成）**
4. 新增操作历史页面，统一查看返航与告警确认记录，并支持按类型和结果筛选。**（已完成）**
5. 统一接口错误提示和加载状态，避免控制失败时页面没有明确反馈。**（已完成）**

**完成标准**：

- 未登录或无权限角色不能发起返航。
- 每次返航、告警确认都可在历史页面和接口中查到。
- 正常、低电量、离线、高风险天气四类返航结果均可复现并显示原因。
- 后端测试、前端构建和浏览器操作验收均通过。

**阶段结果**：以上五项均已完成。当前本机演示已具备权限、二次确认、安全检查、持久化留痕、历史回查和易懂的失败提示；关键权限与告警恢复已有自动化测试。前端使用同域接口和代理连接，后续上云无需把服务器地址写进页面代码。共享 MySQL 环境默认禁用演示身份控制，真实登录接入后才能解除该保护。

### 阶段 B：共享部署（可跳过，等云资源准备后执行）

**目的**：让同事通过同一网址访问系统，使用同一份数据。

**开发与部署顺序**：

1. 准备阿里云 RDS MySQL 与 ECS；数据库与后端放在同一私有网络。
2. 用环境变量切换后端到 MySQL，自动执行建表脚本并验证历史数据读写。
3. 将后端和前端部署到 ECS；同事通过浏览器访问，不直接暴露数据库。
4. 配置数据库备份、访问白名单和服务日志。

**完成标准**：

- 两位不同网络的同事能看到同一条新操作记录。
- 数据库密码不在 Git、前端代码或聊天记录中出现。
- 后端重启后数据仍在，页面可显示服务连接失败原因。

### 阶段 C：真实设备接入前准备

**目的**：让模拟数据接口与真实 DJI Cloud API 的替换边界清晰。

**开发顺序**：

1. 定义设备状态、告警、任务和控制指令的统一数据格式。
2. 增加数据来源标识与数据更新时间；过期、离线和格式错误要在页面提示。
3. 将真实 API 凭证改为服务器环境变量，增加请求超时、失败重试和错误日志。
4. 在测试设备上只读验证状态与告警，再申请控制权限。

**完成标准**：

- 模拟与真实数据可通过同一套前端状态模型展示。
- 连接失败、数据过期和认证失败均有后端日志与页面提示。
- 未完成测试设备验收前，不发送真实返航、起飞或降落命令。

### 阶段 D：任务与航线（P1）

**目的**：从“查看正在执行的任务”升级到“安全地创建和安排任务”。

**开发顺序**：航线草稿 → 航点校验 → 任务创建 → 时间安排 → 任务执行记录。

**完成标准**：航线、任务和执行记录均可保存；创建任务前会检查设备状态、天气和权限。

### 阶段 E：成果与智能管控（P2）

**目的**：在可靠数据和任务记录基础上，增加巡检成果查看、统计报表和规则化的自动安全策略。

**进入条件**：阶段 A 至 D 的记录、权限、任务与真实数据链路均稳定后再开始。

## 四、每次开发必须遵守的门槛

1. **开始前**：说明本次属于哪个阶段、要解决什么问题、会改哪些文件。
2. **编码时**：不为展示效果绕过后端安全检查；模拟数据也必须符合飞行和状态变化规律。
3. **完成后**：至少完成与改动相关的构建、接口或浏览器验收；发现限制要明确写出。
4. **记录**：更新 `.project-memory.md`；前端交互更新 `frontend/开发日志.md`；后端、告警、控制和数据变更更新 `docs/业务与操作规范.md`。
5. **提交前**：检查差异和敏感信息；`a.txt`、补丁文件、账号密码和本机数据库文件不纳入提交。

## 五、优先级调整规则

- 新功能先归入 A 至 E 某一阶段；无法归类时先暂停，确认需求后再开发。
- 阶段 A 的安全、权限和留痕未完成前，不提前开发复杂地图、视觉特效或真实控制。
- 界面可以在每个相关功能完成时同步向司空 2 的信息层级靠拢，但不单独开启脱离功能主线的界面重做。
- 云部署可延后，不阻塞阶段 A 的本机开发；但真实多人共享验收必须放到阶段 B。
- 每完成一个阶段，先汇报验收结果并更新本文，再进入下一阶段。

## 六、下一项建议任务

按使用者最新安排，前端第一轮业务页面和核心交互已完成，航线规划继续暂缓。任务创建、成果预览和导出目前仅在前端演示层可用，下一项建议是在取得测试设备和官方认证说明后执行阶段 C 第 4 项：只读验证真实设备状态与告警；如继续扩展业务，应优先为任务和成果接入后端持久化，而不是先开发航线规划。
